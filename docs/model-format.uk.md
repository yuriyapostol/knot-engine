# Legacy KnotModelV1 — формат для рендерингу

[English](model-format.md) | [Українська](model-format.uk.md) · [Документація](../README.uk.md)

Це збережений контракт статичної геометрії для сумісності. Авторитетний доменний формат knot-engine — [KnotAsset v1](knot-asset-v1.uk.md); це окремий контракт, а не KnotModelV2. Обидва мають власний schemaVersion: 1. Див. [архітектуру міграції](architecture.uk.md).

Формат описує геометрію незалежно від інтерфейсу, локалізації та способу зберігання. JSON з контрольними точками є авторським джерелом, mesh та preview — похідні результати. Машинна JSON Schema є в schema/knot-model-v1.schema.json, TS типи й runtime validator — у src/core. Семантичні перевірки на зразок дубльованих точок виконує runtime validator.

Приклад: [prototype-loop.json](../examples/models/prototype-loop.json). Це технічна модель для демонстрації геометрії; її назва не засвідчує відповідність конкретному практичному вузлу.

## Поля

| Поле | Контракт |
| --- | --- |
| schemaVersion | Обов'язково integer 1 |
| id | Необов'язковий непорожній рядок, до 256 символів; непрозорий ID моделі, може бути багаторівневим |
| coordinateSystem | Обов'язково right-handed-y-up |
| units | Обов'язково relative; абсолютних одиниць і навантажень v1 не описує |
| curves | 1–8 кривих із незалежними ID |
| preview | Необов'язковий preset та camera; за відсутності камера auto-fit |

Curve: id (унікальний рядок до 128 символів), closed:boolean, interpolation:{type:'catmullrom', tension:number}, radius:number, points:[number, number, number][]. Усі ці поля обов'язкові. Початковий v1 підтримує саме catmullrom з явною tension у межах 0..1 для явного визначення форми кривої; інші режими можуть бути додані як версійовані capabilities після fixture-перевірки, не застосовуються мовчки.

Preview: preset='light-outline-v1'; опційно cameraPosition:[x, y, z], target:[x, y, z], fov:number. Позиція і target задаються разом. fov у межах 10..100 градусів, default 55. Невідомий preset — діагностика UNSUPPORTED_SCHEMA/validation issue, не підміна на випадковий вигляд. У майбутньому preset registry розширюється з явною сумісністю. Демо перемикання теми не переписує preview даних.

## Геометричні правила

- Відкрита крива: 2–512 точок. Замкнена: 3–512; не дублювати першу точку останньою, замикання задає closed.
- Загалом до 2048 точок на модель. Координати скінченні, |coordinate| ≤ 100000; radius > 0 та ≤ 10000. Це початкові ресурсні обмеження, а не фізичні одиниці.
- Заборонені послідовні однакові точки та нульова протяжність. Перевірка близьких точок має scale-aware epsilon; його зафіксувати у validator tests, не вибирати довільний threshold на око.
- closed передається узгоджено кривій та TubeGeometry. Для closed шов перевіряється по позиціях/нормалях і візуально. Для open v1 кінці закриваються пласкими caps; це відповідає вигляду зрізу мотузки, не змінює топологію центральної лінії.
- Розмір сегментації контролює quality renderer, не авторський JSON. Пропоновані профілі: low 64/8, medium 128/12, high 256/16 (поздовжні/радіальні на криву), із загальним budget ≤ 100000 rendered triangles (включно з caps і повторним проходом outline) і DPR ≤ 2. Перед allocation зменшувати tessellation до нижчого профілю з warning, якщо профіль перевищує budget; якщо навіть low не вкладається — LIMIT_EXCEEDED. Для складних моделей недостачу дискретизації показує warning; остаточні профілі перевірити на реальних assets.
- Камера не може мати position=target; вихід за видимі межі/занадто близька до моделі позиція дає warning і auto-fit. Невалідні типи/NaN — error, не fallback, що приховує помилку автора.

Числа bounds перевіряються до створення великих typed arrays. Валідатор перевіряє plain JSON-compatible data, відхиляє невідомі ключі в strict authoring/CI режимі, не виконує код і не читає зовнішні посилання. Runtime mode має ту саму перевірку обов'язкової семантики; підтримку майбутніх schema versions не вгадує.

Перехрещення/самоперетини центральної лінії або оболонки не перевіряються повною фізичною моделлю. Успішна schema validation не гарантує фізичної можливості чи правильності навчального вузла. Формат не описує математичну класифікацію чи механічну міцність вузла.

## Версіонування

Schema version, npm package version і renderer preset version — окремі величини. Breaking зміна значення полів/інтерполяції піднімає schemaVersion; новий вигляд preset має нове ім'я. Виправлення геометричного builder може змінити картинки: rendererVersion враховується у cache key preview.

JSON не містить JS, custom shader, image URL, готових Three.js objects або функцій. Власний model loader host передає parse/validated data до viewer. Не вводимо прихований fetch у format resolver. Компонент може використовувати дані з будь-якого джерела, що відповідають цьому формату.

## Приклад моделі

У fixture задано шість точок, tension 0.7 та closed=true. Замикання застосовується до всієї геометрії, шов перевіряється окремо. Камера [0,10,26], target [0,0,0], fov 55 і light-outline preset задають початковий вид. Товщина outline визначається preset відносно radius, щоб однаково працювати в різних масштабах.

## Історичні орієнтири наступних кроків

Legacy KnotModelV1 не отримує steps/timeline. Representations, snapshots, algorithms і steps вже визначені окремим KnotAsset v1. Історичні ідеї named poses, IDs контрольних точок, тривалостей, easing і локалізованих текстів не є реалізованими полями KnotModelV1 або обіцянкою KnotAsset v1. Transitions і trajectories залишаються поза новим контрактом. Для старих споживачів потрібна явна статична модель або adapter.

Інтерполяція координат без контролю перетинів не доводить коректність зав'язування. Потрібні авторські проміжні poses/траєкторії та перевірені transitions; фізичний solver не є неявною обіцянкою формату.
