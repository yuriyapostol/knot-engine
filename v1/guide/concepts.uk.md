# Дані, контракти та ресурси

Специфікація визначає значення даних і поведінку реалізації. JSON Schema перевіряє структурну частину цього контракту. Приклад демонструє його; ресурс — це конкретний запис для повторного використання, що відповідає контракту.

## Що реалізовано

[Специфікація `Knot`](../specifications/knot.uk.md), її [схема](../schema/knot.schema.json) і [контракт компонента](../specifications/components.uk.md) описують поточний пакет.

## Що запропоновано

[Ширший проєкт `Knot`](../../design/knot-knot-draft.uk.md) містить також майбутні формати й твердження. Єдині представлення та самостійні спільні ресурси вже реалізовано в межах [початкового профілю](../specifications/knot.uk.md). Точні підтримувані поля визначає чинна специфікація.

Каталог визначає систему ідентифікації, зокрема назву каталогу та його позначення записів. Реєстр типів представлень містить конкретні визначення типів. Ракурс зберігає налаштування камери. Це різні види ресурсів, тому `resources/catalogs/` не є загальною назвою для всіх них.

## Програмні контракти

API пакета — це імпорти, функції, параметри компонентів, події, методи та типи. Він не означає HTTP-сервер. Контракти даних описують значення запису про вузол; контракти компонентів — як застосунок його відображає. Обидва є специфікаціями, організованими за предметом опису.

## Мова та ідентичність

Англійські й українські сторінки описують ті самі контракти та використовують спільні машинні схеми й приклади даних. Зміна мови документації не перейменовує поля чи ідентифікатори ресурсів. Сам JSON-запис може містити назви кількома мовами.

## Джерела та внесок

Каталог визначає систему ідентифікаторів, джерело — походження даних, внесок — виконану людиною або командою роботу. Ці ролі не підміняють одна одну. Усі метадані необов’язкові; ліцензія задається глобально для об’єкта `Knot`. [Деталі контракту](../specifications/sources.uk.md).
