# Компоненти перегляду

`KnotViewer` вибирає та делегує одне статичне представлення [`RawKnot` або підготовленого `Knot`](prepared-model.uk.md). Вбудовані переглядачі показують 2D-криві через `Knot2DViewer`, 3D-криві й сітки через `Knot3DViewer` і мозаїки через `KnotMosaicViewer`. Сіткові діаграми, PD і DT не мають вбудованих переглядачів. Для оновлення даних замініть вхідні об’єкти; глибока зміна на місці не підтримується. Вибір і перевірка передують виділенню ресурсів відображення.

| Властивість компонента | Значення |
| --- | --- |
| `knot?: RawKnot \| Knot \| null` | Вхід; null/відсутність показує порожній стан |
| `label: string` | Обов’язковий доступний підпис |
| `representationId?: string` | Явний вибір; інакше потрібне рівно одне підтримуване представлення |
| `registry?: ViewerRegistry` | Реєстр компонентів лише головного переглядача; замінює вбудовані записи |
| `view?: Reference \| ViewDefinition` | Явний ракурс застосунку |
| `views?: ViewDefinition[]` | Ракурси застосунку для локального пошуку |
| `registries?: RawResourceRegistry[]` | Явні визначення зовнішніх ресурсів |
| `initialCamera?: Camera3D` | Перевизначення екранної 3D-камери |
| `preserveCamera?: boolean` | Зберігати поточну 3D-камеру, наближення й ціль при зміні представлення або якості в межах того самого вхідного об’єкта; типово false |
| `description?`, `poster?` | Доступний опис; poster — резервне 3D-зображення |
| `locale?: 'uk' \| 'en'`, `messages?` | Мова UI (типово uk); перевизначення повідомлень стосується 3D |
| `theme?: 'light' \| 'dark'` | Типово light |
| `quality?: 'low' \| 'medium' \| 'high'` | Якість 3D, типово medium; бюджет трикутників може її зменшити |
| `active?`, `interactive?`, `showControls?` | Булеві перемикачі, типово всі true |

Спеціалізовані переглядачі приймають відповідні властивості напряму й вибирають лише підтримуваний тип. Головний компонент передає властивості, виклики методів, події та доступні слоти. Вибір ракурсу, режими камери, функції реєстру та значення помилок описано в [контрактах переглядачів](viewer-contracts.uk.md).

З `preserveCamera` перше представлення визначає кадрування; наступні кроки зберігають його замість повторного вміщення кожної форми. Заміна `knot`, `view`, `views`, `registries` або `initialCamera`, очищення входу чи помилка завантаження скидають збереження. `resetView()` і `fitToView()` і далі явно змінюють кадрування поточної форми. Глибина в перспективній проєкції може впливати на видиму товщину мотузки; фіксована ортографічна камера забезпечує однаковий екранний масштаб на будь-якій глибині.

Події: `ready({knotId?,schemaVersion:1,warnings})`, `error({code,message,issues?,recoverable})`, `view-change`. 3D також надсилає `camera-change(CameraView)`; просторовий ракурс є повною фіксованою камерою з `position`, `target`, `up`, `projection` і перспективним FOV у радіанах. Мозаїчні зміни ракурсу містять `{center:[x,y],height}`. Помилки вибору компонента використовують коди вибору ядра; спеціалізовані переглядачі — `INVALID_MODEL` для некоректного входу/ракурсу. 3D також повідомляє `UNSUPPORTED_SCHEMA`, `LIMIT_EXCEEDED`, `WEBGL_UNAVAILABLE`, `CONTEXT_LOST`, `RENDER_FAILED`, `CAPTURE_FAILED` за відповідних умов.

Методи: `resetView()`, `fitToView()`, `capture(options?): Promise<Blob>`. Знімок приймає `width`, `height`, `format`, `view:'current'|'model-preview'`, `transparent`; розміри — цілі числа в 1..2048. 3D підтримує `image/png` (типово 512×512); мозаїка — `image/svg+xml` (типово 1024×1024). `current` зберігає локальне кадрування; `model-preview` використовує розв’язану просторову камеру/типове значення або повну область мозаїки. Знімок не змінює екранного ракурсу.

Слоти 3D: `toolbar({reset,fit,zoomIn,zoomOut,ready,touchActive})`, `fallback({state,error,poster})`, `loading({state})`. Стани: `empty`, `initializing`, `ready`, `error`; SSR створює стабільне резервне відображення без WebGL. Мозаїка надає слоти панелі й резервного відображення та показує коректний вхід безпосередньо як SVG, включно з SSR. Вона не має асинхронного стану завантаження або поведінки poster.

3D прибирає обробники, спостерігачі та ресурси GPU під час демонтування й призупиняє відображення при неактивності, прихованій вкладці або виході за область перегляду. Кнопки панелі, стрілки клавіатури й сенсорне обертання/масштабування керують камерою. Мозаїка підтримує масштабування колесом і панорамування вказівником без WebGL. Перевірка реальних touch/WebView відокремлена від headless-перевірок. Автоматичного завантаження й анімації немає. Бюджет 3D-геометрії — 100 000 трикутників; якість зменшується до виділення ресурсів, або операція завершується помилкою, якщо низька якість досі завелика.

Для всіх візуальних компонентів імпортуйте `knot-engine/styles.css`. Окремі точки входу `knot-engine/3d` та `knot-engine/mosaic` експортують спеціалізовані переглядачі; коренева точка — всі переглядачі й функції реєстру.

## Простір імен CSS та оформлення

Спільний кореневий клас вбудованих переглядачів — `.knot-engine-v1-viewer`; класи частин — `.knot-engine-v1-viewer__surface`, `.knot-engine-v1-viewer__canvas`, `.knot-engine-v1-viewer__fallback`, `.knot-engine-v1-viewer__poster`, `.knot-engine-v1-viewer__toolbar`. Корінь має `data-theme="light|dark"` і `data-state="empty|initializing|ready|error"`.

Простір імен CSS пакета — `knot-engine-v1`; `viewer` спільний для вбудованих переглядачів. Мозаїчний SVG додатково використовує `.knot-engine-v1-mosaic`. Нові сімейства компонентів можуть мати власні назви під префіксом пакета/покоління. `v1` охоплює пакети `0.x` і подальші `1.x`; наступні покоління використовують класи `.knot-engine-v2-viewer…` та змінні `--knot-engine-v2-viewer-*`. Це дозволяє використовувати різні мажорні версії на одній сторінці. Незаверсійовані псевдоніми не додаються.

На початковій стадії розробки зворотна сумісність не вимагається, зокрема й для CSS. Простір імен не фіксує класи, змінні, розмітку або оформлення між випусками одного покоління й не гарантує взаємозамінність їхніх таблиць стилів. Кожний переглядач слід використовувати зі стилями відповідного випуску.

Переважний спосіб налаштування — публічні CSS-змінні `--knot-engine-v1-viewer-*`. Задавайте їх на контейнері для наслідування або на конкретному компоненті через `class`/`style`. Пакет не присвоює публічним змінним власні значення на корені: якщо перевизначення немає, застосовується типове значення. Приватні змінні `--_knot-engine-v1-viewer-*` зберігають палітру теми й не є публічним API. Явне перевизначення має пріоритет в обох темах; для різних кольорів тем застосунок може використати селектор `[data-theme=dark]`.

```vue
<template>
  <section class="knot-gallery">
    <KnotViewer :knot="knot" label="Rope" />
    <KnotViewer :knot="otherKnot" label="Other rope"
      style="--knot-engine-v1-viewer-background: #ffffff" />
  </section>
</template>

<style>
.knot-gallery {
  --knot-engine-v1-viewer-radius: 0px;
  --knot-engine-v1-viewer-aspect-ratio: 1;
  --knot-engine-v1-viewer-toolbar-gap: 8px;
}
</style>
```

Ці змінні оформлюють HTML-інтерфейс, а не WebGL-матеріали, освітлення чи фон PNG. Властивість `theme` продовжує керувати палітрою 3D; `capture` використовує власний фон відповідно до теми/режиму, або прозорий при `transparent:true`. Менші кнопки можуть погіршити зручність сенсорного керування; типово збережено 44px.

Це рішення проєкту: назви пакета, покоління й компонента розділяють стилі різних компонентів і мажорних версій. Наслідувані змінні дозволяють оформлювати групу чи один екземпляр без зміни внутрішньої розмітки. Правила публікації описані в [design](../../design/publication.uk.md).
