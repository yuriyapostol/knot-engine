# Компоненти перегляду

`KnotViewer` вибирає та делегує одне статичне представлення [`RawKnot` або підготовленого `Knot`](prepared-model.uk.md). Вбудовані переглядачі показують 2D-криві через `Knot2DViewer`, 3D-криві й сітки через `Knot3DViewer` і мозаїки через `KnotMosaicViewer`. Сіткові діаграми відображає `KnotGridViewer`; PD і DT не мають вбудованих переглядачів. Для оновлення даних замініть вхідні об’єкти; глибока зміна на місці не підтримується. Вибір і перевірка передують виділенню ресурсів відображення.

| Властивість компонента | Значення |
| --- | --- |
| `knot?: RawKnot \| Knot \| null` | Вхід; null/відсутність показує порожній стан |
| `label: string` | Обов’язковий доступний підпис |
| `representationId?: string` | Явний вибір; інакше потрібне рівно одне підтримуване представлення |
| `registry?: ViewerRegistry` | Реєстр компонентів лише головного переглядача; замінює вбудовані записи |
| `view?: Reference \| ViewDefinition` | Явний ракурс застосунку |
| `views?: ViewDefinition[]` | Ракурси застосунку для локального пошуку |
| `registries?: RawResourceRegistry[]` | Явні визначення зовнішніх ресурсів |
| `initialCamera?: Camera3D` | Перевизначення екранної 3D-камери |
| `preserveCamera?: boolean` | Зберігати поточну 3D-камеру, наближення й ціль при зміні представлення або якості в межах того самого вхідного об’єкта; типово false |
| `description?`, `poster?` | Доступний опис; poster — резервне 3D-зображення |
| `locale?: 'en' \| 'uk'`, `messages?` | Мова UI (типово en); перевизначення повідомлень стосується всіх вбудованих переглядачів |
| `theme?: 'light' \| 'dark'` | Типово light |
| `quality?: 'low' \| 'medium' \| 'high'` | Якість 3D, типово medium; бюджет трикутників може її зменшити |
| `active?`, `interactive?`, `showControls?` | Булеві перемикачі, типово всі true |

Англійська (`en`) є типовою мовою всіх переглядачів, включно з окремими точками входу. Українську вмикають явно через `locale="uk"`. У списках мов англійська стоїть першою; масиви локалізованих даних не визначають мову UI.

Спеціалізовані переглядачі приймають відповідні властивості напряму й вибирають лише підтримуваний тип. Головний компонент передає властивості, виклики методів, події та доступні слоти. Вибір ракурсу, режими камери, функції реєстру та значення помилок описано в [контрактах переглядачів](viewer-contracts.uk.md).

З `preserveCamera` перше представлення визначає кадрування; наступні кроки зберігають його замість повторного вміщення кожної форми. Заміна `knot`, `view`, `views`, `registries` або `initialCamera`, очищення входу чи помилка завантаження скидають збереження. `resetView()` і `fitToView()` і далі явно змінюють кадрування поточної форми. Глибина в перспективній проєкції може впливати на видиму товщину мотузки; фіксована ортографічна камера забезпечує однаковий екранний масштаб на будь-якій глибині.

Події: `ready({knotId?,schemaVersion:1,warnings})`, `error({code,message,issues?,recoverable})`, `view-change`. 3D також надсилає `camera-change(CameraView)`; просторовий ракурс є повною фіксованою камерою з `position`, `target`, `up`, `projection` і перспективним FOV у радіанах. Зміни 2D, сіткового й мозаїчного ракурсу містять `{center:[x,y],height}`. Помилки вибору компонента використовують коди вибору ядра; спеціалізовані переглядачі — `INVALID_MODEL` для некоректного входу/ракурсу. 3D також повідомляє `UNSUPPORTED_SCHEMA`, `LIMIT_EXCEEDED`, `WEBGL_UNAVAILABLE`, `CONTEXT_LOST`, `RENDER_FAILED`, `CAPTURE_FAILED` за відповідних умов.

Методи: `resetView()`, `fitToView()`, `capture(options?): Promise<Blob>`. Знімок приймає `width`, `height`, `format`, `view:'current'|'model-preview'`, `transparent`; розміри — цілі числа в 1..2048. 3D підтримує `image/png` (типово 512×512); 2D, сіткові діаграми й мозаїка — `image/svg+xml` (типово 1024×1024). `current` зберігає локальне кадрування; `model-preview` використовує розв’язану просторову камеру/типове значення або повну область сітки/мозаїки. Для 2D прев’ю використовує розв’язаний плоский ракурс або типове кадрування геометрії. PNG використовує те саме тональне перетворення, експозицію та перетворення у sRGB, що й екранне зображення; кольори поточної теми зберігаються в режимі `current`. Знімок відновлює розмір і щільність пікселів екранного canvas та не змінює екранного ракурсу.

Слоти 3D: `toolbar({reset,fit,zoomIn,zoomOut,ready,touchActive})`, `fallback({state,error,poster})`, `loading({state})`. Стани: `empty`, `initializing`, `ready`, `error`; SSR створює стабільне резервне відображення без WebGL. 2D, сіткові діаграми й мозаїка надають слоти панелі й резервного відображення та показують коректний вхід безпосередньо як SVG, включно з SSR. Вони не мають асинхронного стану завантаження або поведінки poster.

3D прибирає обробники, спостерігачі та ресурси GPU під час демонтування й призупиняє відображення при неактивності, прихованій вкладці або виході за область перегляду. Кнопки панелі, стрілки клавіатури й сенсорне обертання/масштабування керують камерою. 2D, сіткові діаграми й мозаїка підтримують масштабування колесом і двома пальцями та панорамування одним вказівником без WebGL. Після відпускання одного пальця панорамування продовжується без стрибка; скасування жесту, скидання ракурсу й вимкнення взаємодії очищують стан вказівників. 2D і сіткові діаграми також підтримують панорамування стрілками, масштабування +/− і скидання клавішею Home; неактивний або неінтерактивний компонент ігнорує жести. У 3D «Умістити модель» (`fitToView()`) центрує поточну модель і підбирає масштаб, зберігаючи напрямок огляду, вектор up, тип проєкції та кут поля зору перспективної камери. «Скинути вид» (`resetView()`) відновлює початкову камеру. У 2D і сіткових діаграмах reset відновлює запитаний плоский ракурс, а fit уміщує всю геометрію або сітку. Перевірка реальних touch/WebView відокремлена від headless-перевірок. Автоматичного завантаження й анімації немає. Бюджет 3D-геометрії — 100 000 трикутників; якість зменшується до виділення ресурсів, або операція завершується помилкою, якщо низька якість досі завелика.

Для всіх візуальних компонентів імпортуйте `knot-engine/styles.css`. Окремі точки входу `knot-engine/2d`, `knot-engine/3d`, `knot-engine/grid` та `knot-engine/mosaic` експортують спеціалізовані переглядачі; коренева точка — всі переглядачі й функції реєстру.

## Переглядач геометрії 2D

`Knot2DViewer` показує відкриті й замкнені ламані та криві Catmull–Rom (uniform із явним tension, centripetal або chordal) та змішані прямі/квадратичні/кубічні сегменти Безьє як SVG із проходженнями над і під у перетинах.

Упорядковані записи `crossings` мають відповідати геометрії. Виявлені дотики, контакти кінців, збіжні ділянки й кілька перетинів в одній позиції відхиляються. Пошук перетинів Catmull–Rom і Безьє є наближеним: квадратичні сегменти точно переводяться в кубічні, які розбиваються з межею відстані контрольного многокутника `1e-5` від розмаху заданих точок і максимальною глибиною 20. Повністю вироджені криві відхиляються. Ліміт відображення — 2048 сегментів після розбиття кривих і 4096 перетинів; перевищення будь-якого ліміту дає помилку. `validateGeometry2D` перевіряє структуру й пари записів; геометричну відповідність перевіряє переглядач.

`capture()` експортує самодостатній SVG. Розриви в перетинах залишаються прозорими на довільному фоні. Фон типово прозорий; `transparent:false` додає колір фону переглядача.

## Простір імен CSS та оформлення

Спільний кореневий клас вбудованих переглядачів — `.knot-engine-v1-viewer`; класи частин — `.knot-engine-v1-viewer__surface`, `.knot-engine-v1-viewer__canvas`, `.knot-engine-v1-viewer__fallback`, `.knot-engine-v1-viewer__poster`, `.knot-engine-v1-viewer__toolbar`. Корінь має `data-theme="light|dark"` і `data-state="empty|initializing|ready|error"`.

Простір імен CSS пакета — `knot-engine-v1`; `viewer` спільний для вбудованих переглядачів. 2D SVG використовує `.knot-engine-v1-geometry2d`; сітковий SVG — `.knot-engine-v1-grid`; мозаїчний SVG додатково використовує `.knot-engine-v1-mosaic`. Нові сімейства компонентів можуть мати власні назви під префіксом пакета/покоління. `v1` охоплює пакети `0.x` і подальші `1.x`; наступні покоління використовують класи `.knot-engine-v2-viewer…` та змінні `--knot-engine-v2-viewer-*`. Це дозволяє використовувати різні мажорні версії на одній сторінці. Незаверсійовані псевдоніми не додаються.

На початковій стадії розробки зворотна сумісність не вимагається, зокрема й для CSS. Простір імен не фіксує класи, змінні, розмітку або оформлення між випусками одного покоління й не гарантує взаємозамінність їхніх таблиць стилів. Кожний переглядач слід використовувати зі стилями відповідного випуску.

Переважний спосіб налаштування — публічні CSS-змінні `--knot-engine-v1-viewer-*`. Задавайте їх на контейнері для наслідування або на конкретному компоненті через `class`/`style`. Пакет не присвоює публічним змінним власні значення на корені: якщо перевизначення немає, застосовується типове значення. Приватні змінні `--_knot-engine-v1-viewer-*` зберігають палітру теми й не є публічним API. Явне перевизначення має пріоритет в обох темах; для різних кольорів тем застосунок може використати селектор `[data-theme=dark]`.

## Координатні орієнтири

Усі вбудовані переглядачі та `KnotViewer` приймають прикладний prop `guides?: ViewerGuides`. Він не змінює дані вузла, пресети камери або межі для вписування. Типово всі орієнтири приховані.

```vue
<KnotViewer
  v-model:guides="guides"
  :knot="knot"
  label="Вузол"
  locale="uk"
/>
```

```ts
import { ref } from 'vue'
import type { ViewerGuides } from 'knot-engine'
const guides = ref<ViewerGuides>({
  grid: { visible: true, step: 'auto', planes: ['xy'] },
  axes: { visible: true, ticks: true, labels: true },
})
```

Кожне вкладене поле необов’язкове. `grid.step` приймає `'auto'` (типово) або скінченне додатне число в координатах даних; некоректні числа замінюються автоматичним кроком. `planes` вибирає площини 3D (`'xy' | 'xz' | 'yz'`), типово `['xy']`; порожній список приховує всі площини сітки. SVG-переглядачі ігнорують вибір площин. Grid і mosaic завжди використовують крок клітинок 1. Автоматичний крок геометрії вибирається з послідовності 1/2/5. Щільні явно задані сітки геометрії та підписи поділок обмежуються заради скінченного обсягу роботи; частина проміжних ліній або підписів може пропускатися.

Панель керування видима лише при наведенні на переглядач або фокусі всередині нього, включно з кнопками та меню. Вона ховається, коли немає ні наведення, ні фокусу всередині. Приховані кнопки залишаються доступними через Tab і показують панель після отримання фокусу. Стандартні символи кнопок мають розмір 22px; розмір кнопок залишається 44px, а непрозорість фону панелі — приблизно 65%.

Стандартна панель містить кнопку **Орієнтири**, яка відкриває налаштування сітки, осей/індексів, поділок і координатних підписів; у 3D додатково доступний вибір площин. Поділки та підписи типово ввімкнені, але з’являються лише з видимими осями. Меню враховує `active`, `interactive`, `showControls`, `locale` (типово англійська) та перевизначення повідомлень. Зміни через UI локальні й породжують `update:guides` та `guides-change` з повним значенням `ResolvedViewerGuides`. Використовуйте `v-model:guides`, щоб зберігати налаштування після заміни переглядача. Зміна prop замінює локальні налаштування; об’єкт виклику не мутується. Reset і fit впливають лише на камеру. Слоти toolbar додатково отримують `guides` і `setGuides(value: ViewerGuides)`.

SVG-сітки використовують одну повторювану клітинку `<pattern>` лише з верхньою та лівою сторонами й прямокутник із такою заливкою; grid і mosaic додають лише відсутні нижню та праву сторони, щоб замкнути поле. Патерни мають унікальні для екземплярів ID. Виділення тексту в SVG переглядачів вимкнене, щоб підписи не виділялися під час панорамування та інших жестів. Геометрія 2D покриває видиму площину та показує координатні поділки X/Y; окремого шару меж немає. Орієнтири grid і mosaic покривають `[0,n] × [0,n]`. Їхні індекси починаються з нуля та вирівняні за центрами клітинок: рядки grid зростають угору, mosaic — униз, відповідно до даних. Це індекси, а не геометричні координати центрів клітинок. Осі індексів проходять уздовж лівого краю поля та нижнього краю для grid або верхнього для mosaic. Поділки центровані на цих осях, а числові підписи розташовані зовні поля, якщо у видимій області достатньо місця, інакше — поруч усередині. Кожна вісь адаптується окремо до панорамування, масштабу та співвідношення сторін переглядача. Осі доступні й коли сітка прихована.

3D використовує скінченні площини `GridHelper` через початок координат, `AxesHelper` із додатковими від’ємними відрізками, поділками та спрайтовими підписами. Окремих орієнтирів меж немає. Підписи показують значення координат даних без перетворення у фізичні одиниці. Ресурси орієнтирів звільняються після заміни й демонтування. SVG-імпорти не завантажують Three.js. `ViewerGuides`, `ResolvedViewerGuides` та `GuidePlane` експортуються з кореневої та всіх спеціалізованих точок входу. Налаштування експорту й поведінка capture не переглядалися в межах орієнтирів.
