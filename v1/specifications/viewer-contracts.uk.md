# Контракти вибору представлень і переглядачів

**Статус:** модульні 3D- та SVG-мозаїчний переглядачі, вибір представлень, спільні параметри експорту й окремі ракурси застосунку реалізовано.

## Вхід і вибір

Усі компоненти отримують `asset: Asset` (повний або допустимий частковий), `representationId?: string` та окремі `settings`. Наявність схеми, просторів імен, ресурсів, побудов, процедур і станів перевіряється за потребами вибраного представлення. `core` приймає той самий контейнер і не залежить від Vue.

Пропоновані операції `core`:

```ts
type RepresentationQuery = { representationId?: string; type?: string }
type SelectionResult =
  | { ok: true; asset: Asset; representation: Representation; typeUri: string }
  | { ok: false; issues: SelectionIssue[] }
type SelectionIssue = {
  code: 'INVALID_ASSET' | 'REPRESENTATION_NOT_FOUND' | 'AMBIGUOUS_REPRESENTATION'
      | 'UNSUPPORTED_REPRESENTATION' | 'MISSING_DEPENDENCY' | 'INVALID_REPRESENTATION'
  message: string
  path?: string
}
function selectRepresentation(asset: Asset, query?: RepresentationQuery, options?: SelectionOptions): SelectionResult
```

Функція повертає дані, не створює UI, не мутує аргументи та не завантажує ресурси. Тип у запиті порівнюється за розгорнутим URI. Явний ID має збігатися з потрібним типом; відсутність збігів і кілька збігів діагностуються окремо. Універсальний компонент без ID може вибрати представлення лише за однозначним правилом; прихований вибір першого за порядком заборонений. Для часткового активу перевіряється мінімально достатній замкнений набір залежностей. Кореневий контейнер повинен відповідати структурі `Asset` v1; необов'язкові секції можуть бути відсутні. За замовчуванням перевіряються вибране представлення та потрібний йому контекст, а не всі представлення й процедури. `scope: 'all'` вимагає перевірки всього документа. Відсутні залежності вибраного представлення залишаються помилкою.

## Контракт UI

`KnotViewer` визначає компонент за `typeUri`; спеціалізовані переглядачі викликають `selectRepresentation` із фіксованим типом. Спільні стани: `empty | initializing | ready | error`; події: `ready`, `error`, `view-change`. Спільні методи: `resetView()`, `fitToView()`, `capture(options?)`. `camera-change` належить 3D. Події не змінюють `asset`.

```ts
type ViewerRegistration = {
  typeUri: string
  component: unknown // Vue component type in UI package
  capabilities: {
    orbit?: boolean; pan?: boolean; zoom?: boolean; edit?: boolean
    capture?: readonly ('png' | 'svg')[]
    sequences?: boolean
  }
}
type ViewerRegistry = ReadonlyMap<string, ViewerRegistration>
```

Реєстр передається явно або формується локально з вбудованих реєстрацій; не є глобальним змінним станом. Підтримка послідовностей декларується можливістю, але схему кроків і API навігації визначимо окремо.

## Налаштування й міграція

Налаштування переглядача винесено за межі `Asset`. Застосунок передає `view`, необов'язкові локальні ракурси `views`, `initialCamera` для 3D та параметри рендерингу. Поля представлення `views`, `defaultView`, `preferredView` видалено без шару сумісності.

## Перевірки

Тести: повний і частковий актив; явний ID; відсутній та неоднозначний вибір; розгортання префіксів; невідомий тип; відсутні ресурси; незмінність входів; незалежність двох компонентів; підтримка процедур без змішування кроку й ракурсу.


## Окремі точки входу пакета

Пакет експортує `knot-engine/core` для перевірки без UI, `knot-engine/3d` для `Knot3DViewer` і `knot-engine/mosaic` для `KnotMosaicViewer`. Кореневий експорт зберігає `KnotViewer` та обидва спеціалізовані компоненти задля сумісності. Для візуальних компонентів імпортується `knot-engine/styles.css`. Окремі точки входу та їхні декларації TypeScript перевіряються з упакованого npm-архіву.


## Правило вибору універсального переглядача

Без `representationId` компонент `KnotViewer` спочатку залишає представлення, типи яких підтримує чинний реєстр переглядачів, і вибирає представлення **лише за наявності одного такого кандидата**. Непідтримувані сусідні представлення не впливають на вибір, але не видаляються з активу. Якщо підтримуваних представлень декілька (навіть одного типу), потрібен явний ID; якщо немає жодного — `UNSUPPORTED_REPRESENTATION`. Явний ID не допускає автоматичної заміни іншою моделлю. Переданий користувачем реєстр замінює вбудований. Вибране представлення перевіряється в `core` разом із необхідними залежностями.


### Передавання подій

Універсальний компонент надсилає структуровану подію `error` також за помилки вибору переглядача (зокрема неоднозначного або непідтримуваного представлення), а не лише за помилки дочірнього компонента. 3D-переглядач надсилає спільну подію `view-change` разом із наявною `camera-change`; універсальний компонент передає обидві без зміни даних. Нових можливостей взаємодії це не додає.


Інтеграційні тести монтують окремий мозаїчний компонент та універсальний переглядач у DOM, перевіряють передавання подій, відновлення після хибного ID, SVG-відображення без WebGL та незмінність вхідних даних. Вони доповнюють незалежні тести вибору й пакета, але не замінюють наявні браузерні перевірки 3D у Chromium.


Браузерні тести Chromium додатково перевіряють реальний універсальний компонент: перемикання між 3D та SVG-мозаїкою, відсутність нових контекстів WebGL під час відображення мозаїки, вміст SVG-експорту, повідомлення про помилковий ID і відновлення, а також повернення до 3D з PNG-експортом. Формат результату залежить від представлення (PNG для 3D, SVG для мозаїки); наявний підпис `CaptureOptions` збережено для сумісності до окремого очищення API.
