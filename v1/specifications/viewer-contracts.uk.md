# Вибір представлення й контракти переглядачів

Пакет реалізує вибір представлення, делегування через реєстр, 3D та SVG-мозаїчний переглядачі й налаштування ракурсів застосунку. Властивості компонентів описано в [API компонентів](components.uk.md), доменну семантику — в [контракті даних](knot.uk.md).

## Вибір у ядрі

```ts
import { selectRepresentation, type RawKnot, type Knot } from 'knot-engine/core'

type RepresentationQuery = { representationId?: string; type?: string }
// selectRepresentation(knot: RawKnot | Knot, query?, options?): SelectionResult
// Успіх: { ok: true, knot: RawKnot, representation: RawRepresentation, typeUri: string }
// Помилка: { ok: false, issues: SelectionIssue[] }
```

Результат містить нормалізовані сирі дані без UI, зміни входу або завантаження. Типи зіставляються за розгорнутими URI. Явний ID має відповідати також запитаному типу. Відсутні, неоднозначні й непідтримувані збіги мають окремі коди: `INVALID_KNOT`, `REPRESENTATION_NOT_FOUND`, `AMBIGUOUS_REPRESENTATION`, `UNSUPPORTED_REPRESENTATION`, `MISSING_DEPENDENCY`, `INVALID_REPRESENTATION`.

Корінь має відповідати структурі `RawKnot`; необов’язкові розділи можна пропускати. Типово перевіряються вибране представлення й потрібний контекст, включно з каталожними ідентифікаторами предмета опису. Сторонні представлення й процедури не перешкоджають цільовому відображенню. `scope: 'all'` перевіряє весь документ. `registries` та `schemas` передають явні залежності. Успіх вимагає повної перевірки цієї області й зберігає весь нормалізований контекст вузла.

## Вибір переглядача

`KnotViewer` використовує `ViewerRegistry` — `ReadonlyMap<string, ViewerRegistration>` із ключами у вигляді розгорнутих абсолютних URI типів. `createViewerRegistry(entries)` відхиляє повторні ключі; запис має `typeUri`, Vue `component` та readonly `capabilities`. `findViewer(knot, type, registry)` розгортає тип у просторі імен вузла. `selectViewerRepresentation(knot, registry, representationId?)` застосовує правила вибору головного компонента незалежно від відображення.

Вбудовані записи зіставляють `spatial-curve` із `Knot3DViewer`, а `mosaic-diagram` — із `KnotMosaicViewer`. Переданий `registry` замінює вбудовані записи. Без `representationId` має існувати рівно одне представлення із зареєстрованим переглядачем; кілька підтримуваних представлень потребують ID, навіть одного типу. Непідтримувані сусідні представлення ігноруються під час вибору. Явний ID не має резервного варіанта. Відсутність зареєстрованих кандидатів дає `UNSUPPORTED_REPRESENTATION`; відсутні або некоректні колекції представлень отримують діагностику ядра.

Спеціалізовані переглядачі викликають вибір ядра з фіксованим типом і також потребують ID за кількох збігів. Усі переглядачі приймають `RawKnot` або підготовлений `Knot` із потрібним контекстом вибраного представлення. Сам ресурс типу не реєструє засіб відображення. Реєстри не завантажують код або дані.

Можливості оголошують `orbit`, `pan`, `zoom`, `edit`, формати знімків `png`/`svg` та `sequences`. Вбудований 3D підтримує обертання/панорамування/масштабування й PNG; мозаїка — панорамування/масштабування та SVG. Схеми послідовностей і навігацію не реалізовано.

## Ракурси застосунку

Застосунок передає `view`, необов’язкові локальні ракурси `views`, 3D `initialCamera` та параметри відображення окремо від даних вузла. `resolveRepresentationView(requested, views?, registries?, namespaces?)` розв’язує вкладений `ViewDefinition`, локальний `{id}` або глобальний `{ref}`. Локальний пошук вимагає одного відповідного ракурсу; глобальний розгортає оголошені префікси й читає явні реєстри. Відсутні/конфліктні визначення та невалідні ракурси є помилками. Відсутність `view` повертає `null`, залишаючи типове кадрування переглядачу.

`ViewDefinition` вимагає `id`, `name`, `space`, `camera`; `description` необов’язковий. `space: 'space'` використовує `Camera3D`; `space: 'plane'` — `{mode:'plane',center:[x,y],height:додатне}`. Поворот не приймається. Простір ракурсу має відповідати спеціалізованому переглядачу.

Просторовий `fit` вимагає скінченних ненульових неколінеарних векторів `direction` та `up` і `projection`. Напрямок іде від фокуса до камери. Необов’язковий `padding` — щонайменше 1, типово 1.1. `fixed` вимагає різних `position`/`target`, непаралельного `up` і проєкції. Перспектива використовує `0 < fovY < π` радіан; фіксована ортографічна проєкція додатково вимагає додатного `height`. Пропорції області перегляду й межі геометрії визначають вписування. `initialCamera` перевизначає екранну 3D-камеру після розв’язання ракурсу; некоректний запитаний ракурс залишається помилкою.

Набори параметрів камери не належать `RawKnot`. Зміна ракурсу, взаємодія й знімки залишають доменні дані незмінними. Стани конструкцій і кроки процедур мають незалежне значення.

## Події, методи й знімки

Спільні методи — `resetView()`, `fitToView()` та `capture(options?): Promise<Blob>`. Спільні події — `ready`, `error` та `view-change`; 3D додатково надсилає `camera-change` з тим самим описом камери. Мозаїчний `view-change` містить `{center:[x,y],height}`. Головний компонент передає події й сам надсилає структуровані помилки вибору.

`CaptureOptions` містить `width`, `height`, `format`, `view` та `transparent`. Розміри — цілі числа в 1..2048. 3D створює PNG, типово 512×512; мозаїка — SVG, типово 1024×1024. Відсутній формат означає формат переглядача; явно непідтримуваний формат відхиляється. `current` захоплює локальний стан перегляду; `model-preview` використовує розв’язаний просторовий ракурс/типову камеру або повну область мозаїки. 3D-перевизначення `initialCamera` не використовується для попереднього перегляду. Знімок не змінює екранного ракурсу. PNG підтримує прозорий фон; мозаїчний SVG не має заливки фону.

## Точки входу пакета й перевірки

`knot-engine/core` надає операції без UI, `knot-engine/3d` експортує `Knot3DViewer`, а `knot-engine/mosaic` — `KnotMosaicViewer` без Three.js. Коренева точка експортує всі переглядачі та функції реєстру. Для візуальних компонентів імпортуйте `knot-engine/styles.css`.

Перевірки охоплюють вибрану/повну валідацію, повний і частковий контекст, розгортання URI, неоднозначний/непідтримуваний вибір, незалежні налаштування, незмінність входу, самостійне/делеговане відображення в DOM, передавання подій, перемикання 3D/мозаїки в Chromium, SVG/PNG та запаковані точки входу JavaScript/TypeScript.
