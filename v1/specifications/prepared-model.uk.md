# Підготовлена об’єктна модель

`RawKnot` — серіалізований документ (`schema: "Knot"`); `Knot` — його змінювана форма під час виконання. `Subject`, `Representation`, `Procedure` та `Step` додають методи пошуку й локалізації до сирих сутностей. JSON Schema описує серіалізовані дані.

```ts
import { Knot, configureLocalization, STANDARD_RESOURCES } from 'knot-engine/core'
configureLocalization({ locale: 'en', fallbackLocale: 'en' })
const knot = Knot.from(raw, { registries: [STANDARD_RESOURCES] })
const rep = knot.getRepresentation('view-3d')
console.log(rep?.getName(), rep?.getTypeDefinition()?.getName())
const report = knot.validate()
const saved = knot.toRaw()
const independent = knot.clone()
```

## Підготовка й перевірка

`Knot.from(raw, options?)` копіює сирий вхід і готує методи сутностей та ресурсний контекст. Підготовка не встановлює валідності або повноти; для звіту використовуйте `Knot.validate(raw, options?)` або `knot.validate(options?)`. Відсутні ресурси не заважають підготовці, якщо форма входу дозволяє її виконати. Передавання наявного `Knot` у `Knot.from()` повертає той самий екземпляр; для незалежної копії використовуйте `clone()`.

`toRaw()` створює незалежні JSON-сумісні дані; `clone()` готує незалежний граф із підключеними реєстрами й локальними налаштуваннями локалізації. Не використовуйте `structuredClone()` для підготовлених об’єктів. `knot.select({representations?, procedures?})` виділяє самодостатній підготовлений фрагмент. `Knot.compose(parts, options?)` поєднує фрагменти одного документа й відхиляє конфлікти. Обидві операції перевіряють результат.

## Редагування

Властивості й масиви колекцій змінювані. Допоміжні методи готують додані сутності, відхиляють повторні ID та забезпечують зручний пошук/видалення; вони не є транзакціями й не контролюють усі залежності. Видалення дозволене навіть за наявності посилань. Після змін викликайте `knot.validate()`, якщо потрібна валідність документа. Для Vue-переглядачів замініть вхідний об’єкт, щоб спричинити оновлення.

| Сутність | Методи |
| --- | --- |
| Представлення | `getRepresentation(id)`, `addRepresentation(raw)`, `removeRepresentation(id)` |
| Процедури | `getProcedure(id)`, `addProcedure(raw)`, `removeProcedure(id)` |
| Кроки процедури | `procedure.getStep(id)`, `addStep(raw)`, `removeStep(id)` |
| Конструкції | `getConstruction(id)`, `addConstruction(raw)`, `removeConstruction(id)` |
| Стани конструкції | `addConstructionState(constructionId, raw)`, `removeConstructionState(constructionId, stateId)` |
| Предмети конструкції | `addConstructionObject(constructionId, raw)`, `removeConstructionObject(constructionId, objectId)` |
| Вкладені визначення | `addResourceDefinition(kind, raw)`, `removeResourceDefinition(kind, id)` |

Для редагування визначень `kind` — `catalogs`, `representationTypes` або `objectTypes`. Зовнішні реєстри не змінюються. Методи пошуку повертають наявні екземпляри сутностей; видалення повертає `false`, коли запитаний елемент відсутній. Методи додавання копіюють сирий вхід. Використовуйте допоміжні методи, щоб додані сутності отримали свої методи й контекст.

## Ресурсний контекст

`getResource(id, kind?)` повертає стабільну обгортку для конкретного вузла. Ідентичність ресурсу включає вид і розгорнутий URI; передавайте вид для однозначного пошуку. Визначення реєстрів використовуються спільно без копіювання або зміни прототипів. Методи вкладених визначень оновлюють ресурсний контекст; видалення відновлює відповідне визначення реєстру, коли воно доступне.

Стандартні назви ресурсів доступні для відображення без неявного задоволення залежностей валідації. Перевірка використовує явно підключені реєстри; передавання `STANDARD_RESOURCES` залишається рішенням застосунку.

## Локалізація

`LocalizedTexts` — масив записів `{language,value}` з методами `getExact(locale?)` та `get(locale?)`. Точний пошук пробує повний мовний тег і його основу; `get()` додатково пробує налаштовану резервну мову й англійську. Бібліотека не змінює `Array.prototype`. В авторських багатомовних масивах записуйте англійську першою; порядок не визначає пошук або валідність.

`configureLocalization({locale, fallbackLocale, overrides})` задає глобальні типові налаштування. `Knot.from(raw, {locale, fallbackLocale, overrides})` задає локальні параметри вузла, які зберігаються при `clone()` та `select()`. Локальні перевизначення мають пріоритет перед глобальними; налаштування обчислюються під час локалізованих викликів. Зміна глобальної мови не вимагає повторної підготовки.

Методи предмета опису, представлення, процедури й кроку використовують контекст свого вузла. Перевизначення назв/описів задаються за ID сутності або ресурсу. Кроки надають `getInstructions()` із резервним мовним вибором, без перевизначень інструкцій. Тексти UI переглядачів налаштовуються окремо.

Vue-застосунки можуть імпортувати `useLocalizedText(() => representation.getName())` із кореневої точки. Він підписується на глобальні зміни конфігурації й відписується після завершення Vue scope. Споживачі без UI можуть використовувати `subscribeLocalization(listener)`, який повертає функцію відписки.
