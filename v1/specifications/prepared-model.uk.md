# Підготовлена об'єктна модель

Серіалізований документ має тип `RawKnot` (`schema: "Knot"`), а основна модель під час виконання — `Knot`. Підготовлені сутності: `Representation`, `Procedure`, `Step`, `Subject`. Для серіалізованих варіантів використовується префікс `Raw`. JSON Schema описує тільки сирі дані.

```ts
import { Knot, configureLocalization, STANDARD_RESOURCES } from 'knot-engine/core'
configureLocalization({ locale: 'uk', fallbackLocale: 'en' })
const knot = Knot.from(raw, { registries: [STANDARD_RESOURCES] })
const rep = knot.getRepresentation('view-3d')
console.log(rep?.getName(), rep?.getTypeDefinition()?.getName())
const saved = knot.toRaw()
const independent = knot.clone()
```

Підготовлені сутності використовують спільний ресурсний контекст. Повторне звернення за ID повертає той самий об'єкт у межах документа. Стандартні назви ресурсів доступні для відображення без неявного додавання ресурсів до залежностей валідації. Відсутні зовнішні ресурси не перешкоджають підготовці структурно правильного, але семантично неповного документа.

`LocalizedTexts.get(locale?)` вибирає мовний варіант із урахуванням глобальної локалі та резервної мови. Бібліотека не змінює `Array.prototype`. `configureLocalization` налаштовує локаль, резервну мову та перевизначення назв ресурсів. Тексти інтерфейсу переглядачів залишаються окремими.

Структурні зміни виконуються методами `addRepresentation` та `removeRepresentation`; масив представлень заморожено. `toRaw()` повертає JSON-сумісні дані, а `clone()` створює незалежну підготовлену модель. Не використовуйте `structuredClone()` для підготовлених об'єктів. Наявні функції для сирих даних збережено; де передбачено, вони також приймають підготовлені документи.

Це несумісна зміна контракту v1: JSON використовує `schema: "Knot"` і `knot.schema.json`. Публічні операції над документом — методи `Knot`, а не окремі функції.

Локальні налаштування передаються у `Knot.from(raw, { locale, fallbackLocale, overrides })`. Вони застосовуються тільки до відповідного екземпляра й зберігаються при `clone()` та `select()`. Локальні перевизначення мають пріоритет перед глобальними. Мова визначається під час виклику `getName()` або `getDescription()`, тому зміна глобальної локалі не потребує повторної підготовки документа.

Кероване редагування охоплює представлення (`knot.addRepresentation()`, `knot.removeRepresentation()`), процедури (`knot.addProcedure()`, `knot.removeProcedure()`) і кроки (`procedure.addStep()`, `procedure.removeStep()`). Методи `getRepresentation()`, `getProcedure()` і `getStep()` повертають стабільні об'єкти, доки відповідні елементи не видалено. Масиви цих колекцій заморожені, щоб структурні зміни проходили через методи.

Для локальних каталогів і визначень типів передбачено `knot.addResourceDefinition(kind, definition)` та `knot.removeResourceDefinition(kind, id)`, де `kind` — `catalogs`, `representationTypes` або `objectTypes`. Зовнішні реєстри не змінюються. Видалення типу, який використовується представленням, блокується. Видалення локального перевизначення повертає ресурс із підключеного реєстру, якщо він існує.

Для реактивних Vue-інтерфейсів використовуйте `useLocalizedText(() => representation.getName())` з головного експорту пакета. Композабл підписується на `configureLocalization()` і автоматично відписується під час завершення Vue scope. Для використання поза Vue доступний `subscribeLocalization(listener)`, який повертає функцію відписки. Локальна конфігурація конкретного `Knot` і надалі має пріоритет над глобальною.

Визначення ресурсів з реєстрів використовуються без копіювання. Метод `getResource()` повертає стабільну обгортку для кожного вузла.
