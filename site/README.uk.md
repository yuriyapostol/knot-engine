# Сайт та архіви випусків

`npm run build:site` знаходить вихідні каталоги `vN/` у корені й публікує кожен у `site-dist/vN/`. Збережені знімки з `site/releases/` додаються до цієї ж збірки. Workflow Pages публікує весь результат.

Перед архівуванням закомітьте вихідні файли: `release.json` містить їхній коміт і ознаку незбережених змін. Для підготовленого випуску виконайте `npm run site:archive`, перевірте та закомітьте `site/releases/<версія-пакета>/`. Команда відмовляється перезаписувати знімок. Виправлення опублікованого випуску включайте в наступний. Звичайна збірка не створює архівів.

Знімок містить документацію, специфікації, схеми, приклади та автономний інтерактивний приклад поточного покоління. Канонічні ID схем і простори імен залишаються під `/v1/`. Для відтворюваної валідації використовуйте схеми вибраного знімка в ізольованому реєстрі валідатора, не завантажуйте поточні схеми автоматично за канонічними URL.

Джерело архівів — збережені в Git знімки, а не кеш CI чи тимчасові артефакти. `site-dist/` не комітимо. Для запланованих типів ресурсів без реалізованих визначень не публікуємо вигаданих записів.

Кожне покоління має `version.json`, парні англійські й українські Markdown-файли та каталоги `guide/`, `schema/`, `spec/examples/`, `resources/`. Поточне покоління визначає `package.json#knotEngine.resourceDirectory`: воно отримує актуальний інтерактивний приклад і знімок випуску. Файли й експорти npm мають вибирати те саме покоління.

`npm run dev` запускає весь сайт на порту 5173 з автоматичною перебудовою та оновленням браузера. `npm run preview:site` перебудовує й показує готовий сайт на порту 5174; для наступної перебудови повторіть команду. Компонент `site/components/InteractiveExample.vue` використовує переглядач пакета; `site/runtime/` збирає цей компонент для сайту. Матеріали містяться в кореневих `vN/` та `design/`; у `site/` немає їхніх копій для окремих поколінь.

Після запуску сайту `node scripts/site/browser-smoke.mjs` перевіряє перемикання мови, вбудований переглядач і мобільну верстку. Іншу адресу можна задати через `SITE_TEST_URL`; Chrome — через `CHROME_PATH`.
