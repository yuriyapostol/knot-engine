# Архітектура knot-engine

Початковий профіль перегляду `KnotAsset` реалізовано. Авторитетні поточні контракти: [дані](../v1/specifications/knot-asset.uk.md), [функції](../v1/specifications/functions.uk.md), [компонент](../v1/specifications/components.uk.md). [Ширший проєкт](knot-asset-draft.uk.md) ще містить майбутні роботи; це не означає, що всі запропоновані поля вже приймаються.

```text
KnotAsset / самостійні дані / явно передані реєстри
  → структурна перевірка з обмеженням ресурсів
  → розгортання URI, перевірка посилань і доменної семантики
  → звіт повноти
  → вибір представлення й ракурсу
  → RenderableModel
  → побудова геометрії + підготовка камери
  → KnotViewer / знімок PNG
```

Core не містить Vue, Three.js, доступу до браузера або мережевого resolver. Контракти JSON Schema мають спільне джерело `src/core/contracts.json`; незалежні опубліковані схеми генеруються через `npm run build:schemas`. Семантична валідація окремо перевіряє зв’язки між записами й геометричні/комбінаторні правила.

Компонент `KnotViewer` приймає об’єкт `KnotAsset`, вибір представлення та необов’язковий контекст реєстрів/ракурсу. Старий model-вхід, адаптери, схеми й тести сумісності видалено. Спільні помилки й типи рендерингу більше не належать legacy-модулю. Геометрія підтримує polyline та явні uniform/centripetal/chordal Catmull–Rom. Перспективна й ортографічна камери використовують спільну підготовку для екрана та знімків.

Демка сайту використовує лише публічний API. Редагується весь об’єкт `KnotAsset`, зберігається вибір представлення, якщо воно ще існує, а при некоректному редагуванні залишається останній коректний об’єкт `KnotAsset`. Іменовані стани належать конструкціям; кожне статичне представлення позначає свій стан. Процедури вибирають представлення без вимог відповідності для інтерполяції.

Виділення включає потрібні конструкції й ресурси. Композиція обмежена фрагментами одного документа; об’єднання незалежних авторів не виводиться неявно. Дані невідомого типу структурно читаються, але не отримують повного семантичного звіту. Додаткові формати, твердження й анімація потребують власних контрактів і тестів.

Перевірки: типізація, модульні/схемні тести, збірки бібліотеки/демки, браузерні тести, споживач tarball і тести сайту/посилань. Реальні touch, WebView та фізична коректність вузлів цими перевірками не встановлюються. Версії залишаються 0.1.0 для пакета та `schemaVersion` 1.

CSS використовує простір імен пакета `knot-engine`, за яким ідуть мажорне покоління та назва компонента: `.knot-engine-v1-viewer…` і `--knot-engine-v1-viewer-*` для `KnotViewer`. Інші компоненти отримують власні назви в тому самому просторі пакета/покоління. Різні мажорні версії можна використовувати на одній сторінці. На початковій стадії зворотна сумісність CSS, як і решти пакета, не вимагається. Деталі — у [політиці публікації](publication.uk.md#простір-імен-css-для-мажорних-поколінь) та [контракті компонента](../v1/specifications/components.uk.md#простір-імен-css-та-оформлення).
