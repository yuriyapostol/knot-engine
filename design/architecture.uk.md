# Архітектура knot-engine

Пакет розділяє доменні дані, валідацію та відображення. Чинні контракти: [дані](../v1/specifications/knot.uk.md), [підготовлені об’єкти](../v1/specifications/prepared-model.uk.md), [функції](../v1/specifications/functions.uk.md) та [компоненти](../v1/specifications/components.uk.md). [Відкриті проєктні питання](knot-draft.uk.md) стосуються розширень поза цими контрактами.

```text
RawKnot / Knot + явно передані реєстри ресурсів
  → структурна перевірка з обмеженням ресурсів
  → розгортання просторів імен і перевірка залежностей
  → вибір представлення
  → вибір компонента з реєстру переглядачів
      → Knot3DViewer → геометрія + камера → WebGL / PNG
      → KnotMosaicViewer → контури плиток + плоский ракурс → SVG
```

## Ядро й підготовлені об’єкти

`knot-engine/core` містить типи сирих даних, підготовлені об’єкти `Knot`, локалізацію, валідацію, вибір, розв’язання ресурсів і виділення/композицію. Він не завантажує Vue, Three.js або DOM і не звертається до мережі. Спільне джерело контрактів JSON Schema — `src/core/contracts.json`; `npm run build:schemas` генерує окремі опубліковані схеми. Семантичні валідатори окремо перевіряють посилання та геометричні/комбінаторні правила.

`RawKnot` — серіалізовані дані; `Knot.from()` створює підготовлений об’єкт із методами. `toRaw()` повертає незалежну копію для серіалізації. Перевірка всього документа й вибраного представлення мають різні області: відображення вимагає повної перевірки вибраного представлення та потрібного контексту. Сторонні представлення не зобов’язані підтримувати відображення.

Виділення включає потрібні конструкції, визначення типів/каталогів і метадані джерел. Композиція об’єднує фрагменти одного документа й відхиляє конфлікти; збіг предмета опису сам собою не об’єднує незалежні документи.

## Переглядачі й налаштування

`KnotViewer` делегує відображення компоненту, вибраному за розгорнутим URI типу. Вбудований реєстр містить `Knot3DViewer` і `KnotMosaicViewer`; обидва працюють також самостійно. Без явного ID головний компонент вибирає представлення лише тоді, коли підтримуване представлення рівно одне. Власний реєстр замінює вбудовані записи. Визначення ресурсів і реєстрації переглядачів мають різне призначення: визначення типу не встановлює засіб відображення.

Застосунок передає `view`, `views`, 3D `initialCamera` та параметри відображення окремо від даних вузла. Зміни камери, панорамування, масштабування й знімки не змінюють вхід. Системи координат, масштаб, топологія та стани конструкцій залишаються доменними даними. Див. [композицію переглядачів](modular-viewers.uk.md) і [контракти вибору та налаштувань](../v1/specifications/viewer-contracts.uk.md).

3D-переглядач будує polyline або uniform/centripetal/chordal Catmull–Rom геометрію з перспективною/ортографічною камерою. Мозаїчний переглядач малює фіксовану конвенцію 11 плиток у SVG без WebGL. Окремі точки входу `knot-engine/3d` і `knot-engine/mosaic` ізолюють залежності. Сіткові діаграми, PD і DT підтримують валідацію без вбудованих переглядачів.

## Сайт і перевірки

Редактор сайту використовує публічний API пакета, редагує весь вузол, зберігає вибір підтримуваного представлення й залишає останній коректний результат після помилкового редагування. Процедури вибирають ілюстрації без вимог відповідності для анімації. Експорт PNG і SVG відповідає можливостям вибраного переглядача.

Перевірки охоплюють типи, схеми, семантичну валідацію, геометрію, SSR/hydration, DOM-інтеграцію, відображення/знімки в Chromium, споживачів tarball і посилання сайту. Поведінка реальних touch/WebView та фізична коректність вузлів потребують окремої перевірки.

Компоненти спільно використовують класи `.knot-engine-v1-viewer…` та змінні `--knot-engine-v1-viewer-*`; мозаїчний SVG також має `.knot-engine-v1-mosaic`. Простори імен, покоління та випуски описано в [оформленні](../v1/specifications/components.uk.md#простір-імен-css-та-оформлення) і [політиці публікації](publication.uk.md).
