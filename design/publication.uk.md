# Публікація, покоління та мовні версії

Статус: реалізована організація сайту й workflow випусків. Локальна збірка не розгортає сайт і не публікує npm-реліз. Версія пакета 0.1.0 та `schemaVersion` 1 залишаються незмінними.

## Організація вихідних матеріалів

```text
v1/
  index.md / index.uk.md
  guide/
  schema/
  specifications/
  examples/
  resources/
  version.json
design/
site/
  components/
  runtime/
  releases/
src/
tests/
```

Матеріали поколінь зберігаються один раз у кореневих vN. Посібник пояснює виконання задач; специфікації визначають реалізовані контракти даних, компонентів і функцій. Схеми й приклади форматів розміщено поряд зі специфікаціями в schema/ та examples/. Ресурси містять конкретні визначення для повторного використання; каталоги — саме системи ідентифікації. Запропоновані контракти, дослідження, плани приймання й архітектурні рішення розміщуються в design, явно відокремлено від чинних специфікацій.

site містить спільну навігацію, локалізацію, побудову сторінок та оболонку інтерактивного прикладу. Приклади поточного покоління монтуються безпосередньо в контейнери сторінки; лише сторінки з прикладами завантажують локальні для покоління збірки JavaScript і CSS. Стилі демки обмежені `knot-engine-v1-demo` й наслідують палітру сторінки. Він не дублює вихідні матеріали v1/v2. Його знімки випусків — незмінні згенеровані артефакти, а не ще одне дерево для редагування. Компоненти пакета відображають вузли; сайт надає редактор і пояснення. Поточний засіб візуалізації не застосовується мовчки до несумісних старих поколінь: лише поточне покоління отримує поточний інтерактивний runtime. Архівні знімки зберігають власну збірку runtime. Інше активно інтерактивне покоління потребує явно сумісного runtime.

## Дві мовні версії

Англійська використовує name.md, українська — name.uk.md, з однаковими ключами тем. Спільні JSON-схеми й приклади не дублюються. Англійські сторінки мають канонічний маршрут теми, українські — суфікс .uk.html: наприклад, /v1/specifications/knot.html та /v1/specifications/knot.uk.html. Посилання зберігають розширення .html. Головні сторінки сайту й поколінь використовують index.uk.html для української та index.html для англійської. Перемикання мови зберігає тему; навігація, статуси й керування прикладом локалізовані. HTML lang відповідає вибраній мові. Конфігурація site/locales.mjs наразі включає лише en та uk. Відсутній відповідник зупиняє збірку, а не приховано показує іншу мову як переклад.

Матеріали проєктування також мають дві версії за адресами на кшталт /design/architecture.html та /design/architecture.uk.html. Це робочі матеріали поза npm-пакетом, а не версійні runtime-контракти. Посилання з архіву на інше покоління чи design ведуть до відповідних сторінок сайту; власний вміст знімка залишається локальним.

## Спільний випуск і стабільна ідентичність

Пакет, документація, специфікації, схеми й наявні дані утворюють один випуск із номером пакета. v1 включає пакети до 1.0 і подальші 1.x. До стабілізації дозволені несумісні зміни без підвищення поточних номерів.

/v1/ містить актуальні матеріали першого покоління. /releases/<версія-пакета>/ — явно створений незмінний знімок цього покоління. Інші vN публікуються одночасно; незалежної нумерації релізів специфікацій чи даних немає. Поточна документація має видиму позначку розробки; /next/ не потрібен.

Простір імен залишається https://yuriyapostol.github.io/knot-engine/v1/. Перенесення файлів чи документації не перейменовує сутності. Схеми розміщено безпосередньо у v1/schema/ й опубліковано за їхніми канонічними ID під /v1/schema/. Експорти схем пакета вказують на той самий каталог. Назви схем не повторюють суфікс покоління.

Архіви зберігають канонічні ID. Для відтворюваної перевірки схеми обраного знімка передаються в ізольований реєстр, без прихованого завантаження поточних визначень. Різні редакції з одним канонічним ID не можна змішувати в одному реєстрі validator.


## Простір імен CSS для мажорних поколінь

CSS-назви починаються з повного простору імен пакета `knot-engine`, за яким ідуть мажорне покоління та назва компонента. Класи мають форму `knot-engine-vN-<component>` / `knot-engine-vN-<component>__<part>`, змінні компонента — `--knot-engine-vN-<component>-<setting>`. Вбудовані переглядачі спільно використовують `.knot-engine-v1-viewer`, `.knot-engine-v1-viewer__…` та `--knot-engine-v1-viewer-*`; мозаїчний SVG також має `.knot-engine-v1-mosaic`. Нові сімейства компонентів можуть отримувати відмінні назви зі спільним префіксом пакета/покоління.

Різні мажорні версії можна використовувати на одній сторінці. Майбутні `v2`, `v3` тощо використовують власні простори класів і змінних; окремий простір для кожного `0.x` не вводиться.

На початковій стадії зворотна сумісність не вимагається для жодної частини пакета, включно з CSS. Окремих гарантій стабільності класів, змінних чи сумісності таблиць стилів між випусками одного покоління немає. Переглядач використовує стилі свого випуску. Це рішення проєкту про розділення просторів імен; поточні налаштування оформлення описані в [контракті компонента](../v1/specifications/components.uk.md#простір-імен-css-та-оформлення). Опубліковані архівні знімки залишаються незмінними.

## Вибір матеріалів пакета й сайту

package.json вибирає поточне покоління через knotEngine.resourceDirectory, зараз v1. files та exports включають лише це покоління, dist, README й LICENSE; інші покоління, design і архіви сайту виключені. Публічні імпорти залишаються knot-engine/schema/.... При зміні покоління пакета потрібно разом оновити вибір, files і exports. Назва Git-гілки не визначає версію пакета.

Кожен vN/version.json містить packageVersion, `schemaVersion` та status. Версія пакета поточного покоління має збігатися з package.json. Інші покоління зберігають власні метадані. Вихідний код, тести та реалізація сайту залишаються поза vN.

## Команди й політика архівування

- npm run dev: зібрати й відкрити весь сайт на порту 5173, автоматично перебудовувати й оновлювати після змін матеріалів, компонентів, схем або прикладів.
- npm run build:site: створити site-dist з усіма поколіннями, двомовними сторінками й збереженими знімками випусків.
- npm run preview:site: перебудувати й відкрити production-результат на порту 5174.
- npm run site:archive: явно створити site/releases/<версія-пакета>; відмовитися перезаписувати наявний знімок. Команда не публікує npm і не розгортає Pages.
- npm run test:site: перевірити мовні відповідники, маршрути мов, кілька поколінь, посилання й збереження архівів.

GitHub Pages публікує весь site-dist після перевірок на main. Джерело архівів site/releases — довготривалі файли в Git, а не тимчасові кеші CI. Перед знімком слід закомітити вихідні матеріали випуску, щоб метадані вказували їхній commit; наявність незакомічених змін записується. Згенерований знімок перевіряється й включається до релізного коміту; код випусків фіксується Git-тегами. Гілки підтримки потрібні лише для активно підтримуваного старого коду. Опубліковані знімки не редагуються; виправлення входять до наступного випуску.
